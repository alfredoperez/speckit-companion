## Assistant

VS Code stores the first three per machine, so set them in user settings. A workspace `settings.json` can't override them.

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `speckit.aiProvider` | string | `"claude"` | The assistant that gets your commands. The values are the ids under [Providers](#providers). |
| `speckit.permissionMode` | string | `"interactive"` | `"interactive"` lets the CLI ask before it acts. `"auto-approve"` skips the prompts. |
| `speckit.commandFormat` | string | `"auto"` | `"auto"` lets the provider decide. `"dot"` sends `speckit.plan` and `"dash"` sends `speckit-plan`. |
| `speckit.aiContextInstructions` | boolean | `true` | Adds a note to each command asking the assistant to record its progress, so the viewer shows finer steps |

Auto-approve adds `--permission-mode bypassPermissions` for the Claude Code CLI, `--auto-approve` for Oh My Pi, and `--yolo` for Copilot CLI and Qwen Code. The other assistants take no flag. Copilot CLI always runs auto-approved, because it can't show a permission prompt when a command is sent to it.

## Specs and workflows

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `speckit.specDirectories` | string[] | `["specs", ".specify/specs"]` | Where specs are found. `specs` and `apps/*/specs` list their children as specs. A trailing wildcard, as in `openspec/changes/*`, makes each match a spec folder. |
| `speckit.projectFolder` | string | `""` | In a multi-root workspace, the folder treated as the Spec Kit project, by name or path. Empty picks the first folder with `.specify/`, then the first with `specs/`. |
| `speckit.defaultWorkflow` | string | `"speckit"` | The workflow Create New Spec pre-selects: `"speckit"` or `"companion"`. While you haven't set it, installing the Companion extension for Spec Kit makes Companion the pre-selection. |
| `speckit.customWorkflows` | object[] | `[]` | Your own workflows. See [Custom workflows and commands](/docs/customize/your-own-workflow). |
| `speckit.customCommands` | array | `[]` | Your own slash commands, each a string or an object. Same page. |

## Views and notifications

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `speckit.views.steering.visible` | boolean | `true` | Shows the Steering view in the [sidebar](/docs/navigate/viewer-and-sidebar) |
| `speckit.views.settings.visible` | boolean | `false` | Shows the Settings view in the sidebar |
| `speckit.notifications.stepComplete` | boolean | `true` | Notifies when a step or a task phase completes, with an **Open spec** action |

## Companion and telemetry

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `speckit.companion.installPrompt` | boolean | `true` | Offers the Companion extension for Spec Kit when it's missing or out of date, through banners, a status-bar warning and a notification. The activity-bar badge and the row in the Specs view stay either way. |
| `speckit.viewer.activityPanel` | boolean | `true` | Shows each spec's Activity timeline in the viewer. Needs the Companion extension for Spec Kit. |
| `speckit.telemetry` | boolean | `true` | Anonymous usage counts. See [Telemetry](#telemetry). |

## Providers

The first time the extension starts with no provider set, a picker asks for one and saves it to your user settings. After that it's the `speckit.aiProvider` dropdown.

<DocFigure
  src="live-settings-provider.png"
  alt="The Speckit: Ai Provider setting with its dropdown open on twelve assistants, from Claude Code to Antigravity."
  caption="The dropdown lists twelve assistants, and Claude Code is the default."
/>

Choose the provider before you initialize a new project, because Spec Kit sets the project up for that assistant and records it in `.specify/integration.json`. If the file names a different assistant than your setting, the extension says so when it starts and offers **Switch to** that one or **Keep** yours. Switch takes effect after a reload. Keep stops it asking about that pair in this project.

## How each one is reached

| Provider (`aiProvider` value) | Runs as |
| --- | --- |
| Claude Code (`claude`) | `claude` in a terminal |
| Claude Code (VS Code) (`claude-vscode`) | The Claude Code panel, no terminal |
| GitHub Copilot CLI (`copilot`) | `ghcs` / `gh copilot` in a terminal |
| Gemini CLI (`gemini`) | `gemini` in a terminal |
| Codex CLI (`codex`) | `codex` in a terminal |
| Qwen Code (`qwen`) | `qwen` in a terminal |
| OpenCode (`opencode`) | `opencode` in a terminal |
| IDE Chat (`ide-chat`) | Your editor's built-in chat (Copilot, Composer, Cascade) |
| Wibey CLI (`wibey`) | `wibey` in a terminal |
| Wibey (VS Code) (`wibey-vscode`) | The Wibey chat panel, no terminal |
| Antigravity (`antigravity`) | `agy` in an interactive terminal |
| Oh My Pi (`omp`) | `omp` in a terminal |

IDE Chat submits the prompt only in an initialized workspace, where the chat recognizes `/speckit.*`. Otherwise it prefills the prompt and warns.

## What each one reads

Paths are relative to your project, and the Steering view also reads the user-level MCP config at the same path under your home folder. IDE Chat owns none of these.

| Provider | Steering file | Steering folder | Agents | Skills | Hooks | MCP config |
|---|---|---|---|---|---|---|
| Claude Code, and in VS Code | `CLAUDE.md` | `.claude/steering/` | `.claude/agents/*.md` | `.claude/skills/` | `.claude/settings.json` | `.claude/settings.json` |
| GitHub Copilot CLI | `.github/copilot-instructions.md` | `.github/instructions/*.instructions.md` | `.github/agents/*.agent.md` | none | none | `.copilot/mcp-config.json` |
| Gemini CLI | `GEMINI.md` | none | none | none | none | `.gemini/settings.json` |
| Codex CLI | `AGENTS.md` | `.codex/` | none | `.agents/skills/` | none | `~/.codex/config.toml` |
| Qwen Code | `QWEN.md` | `.qwen/steering/` | none | none | none | `.qwen/settings.json` |
| OpenCode | `AGENTS.md` | none | `.opencode/agent/*.md` | none | none | `.opencode/opencode.jsonc` |
| Wibey, CLI and VS Code | `AGENTS.md` | none | `.wibey/agents/*.md` | `.wibey/skills/` | `.wibey/hooks/hooks.json` | `.wibey/.mcp.json` |
| Antigravity | `AGENTS.md` | none | none | none | none | none |
| Oh My Pi | `AGENTS.md` | none | `.omp/agents/*.md` | `.omp/skills/` | `.omp/hooks/pre/*.ts`, `.omp/hooks/post/*.ts` | `.omp/mcp.json` |

## Telemetry

The extension counts anonymously which assistant and workflow you chose, that a step was sent, that a spec was created, opened, completed or archived, which views were opened, and that an install prompt was shown or clicked. Each event carries the extension, VS Code and Spec Kit CLI versions, your platform, and a random id per install and per spec.

It never sends your prompts, file paths, spec names, capability names or the names of your own workflows.

Set `speckit.telemetry` to `false` to turn it off. Turning off VS Code's own `telemetry.telemetryLevel` does the same. Every event and its properties are listed in [docs/telemetry.md](https://github.com/alfredoperez/speckit-companion/blob/main/apps/vscode/docs/telemetry.md) in the repository.
