Slash commands are typed in your assistant and do the work. Palette commands run from the VS Code command palette, and most of them send a slash command for you.

## The steps

| Step | Spec Kit | SpecKit Companion |
| --- | --- | --- |
| [Constitution](/docs/steps#constitution) | `/speckit.constitution` | the same command |
| [Specify](/docs/steps#specify) | `/speckit.specify` | `/speckit.companion.specify` |
| [Plan](/docs/steps#plan) | `/speckit.plan` | `/speckit.companion.plan` |
| [Tasks](/docs/steps#tasks) | `/speckit.tasks` | `/speckit.companion.tasks` |
| [Implement](/docs/steps#implement) | `/speckit.implement` | `/speckit.companion.implement` |
| [Converge](/docs/steps#converge) | `/speckit.converge` | the same command |
| [Mark complete](/docs/steps#mark-complete) | the **Mark Completed** button | `/speckit.companion.mark-complete` |
| [Auto](/docs/steps#auto) | none | `/speckit.companion.auto` |

Both families stay installed, and a spec uses the one it was created with. Some assistants spell these with dashes, as in `/speckit-companion-plan`. The `speckit.commandFormat` [setting](/docs/reference/configuration) picks the form the extension sends.

Spec Kit also has `/speckit.clarify`, `/speckit.checklist`, `/speckit.analyze` and `/speckit.taskstoissues`. The viewer offers them under **Other actions**.

## Run state

These three read the run record, which [Overview and progress](/docs/results/the-overview) covers.

| Command | Use it when |
| --- | --- |
| `/speckit.companion.status` | You want the current step and the next action |
| `/speckit.companion.resume` | A run stopped and you want to continue from the last finished step |
| `/speckit.companion.doctor` | A run looks wrong and you want a health report |

## Living specs

All seven do nothing until [living specs](/docs/results/living-specs) are turned on.

| Command | What it does |
| --- | --- |
| `/speckit.companion.living-adopt` | Drafts a living spec for a code area you name, and registers it |
| `/speckit.companion.living-sync` | Updates every affected living spec from your current changes |
| `/speckit.companion.living-drift` | Lists source files changed since each spec was last committed |
| `/speckit.companion.living-coverage` | Reports which requirements have a test mapped |
| `/speckit.companion.living-show` | Prints a requirement list, one requirement, or the requirements for one file |
| `/speckit.companion.living-validate` | Checks the shape of living specs and of a feature spec's deltas |
| `/speckit.companion.living-move` | Moves a living spec between the central folder and a place beside its code |

The extension installs eight more commands that you never type: seven record a Spec Kit run's step times, and `speckit.companion.classify` sizes a change for the workflow.

## In the command palette

These are under the **SpecKit** category. The context-menu actions on a spec, such as Archive and Reveal, are also listed there and aren't repeated here.

| Command | What it does |
| --- | --- |
| **New Spec** | Opens the Create New Spec panel |
| **Run Spec Hands-Off (Auto)** | Starts a spec with [Auto](/docs/steps#auto) |
| **Specify**, **Plan**, **Tasks**, **Implement** | Send that step's command to your assistant |
| **Clarify**, **Checklist**, **Analyze** | Send Spec Kit's refinement commands |
| **Converge** | Sends `/speckit.converge` for the spec |
| **Create GitHub Issues from Tasks** | Sends `/speckit.taskstoissues`, after you confirm |
| **Constitution** | Sends `/speckit.constitution` |
| **Run Custom Command** | Lists your [custom commands](/docs/customize/your-own-workflow) |
| **New Bug**, **New Idea** | Start a [bug or an idea](/docs/ide/bugs-and-ideas) |
| **Set Up Living Specs**, **Adopt Code Area…** | Turn [living specs](/docs/results/living-specs) on, and register a capability |
| **Sync living specs from my changes**, **Validate living specs** | Send the matching living-specs command |
| **Initialize SpecKit** | Runs `specify init` in the workspace |
| **Install SpecKit CLI** | Installs the `specify` command |
| **Install Companion Extension** | Installs the Companion extension for Spec Kit into the project |
| **Upgrade…** | Upgrades the CLI, the project files, or both |
| **Open a Live Sample** | Opens a finished sample run in the viewer |
| **SpecKit Settings** | Opens [Settings](/docs/reference/configuration) filtered to the extension |
| **Check for Updates** | Checks for a newer version of the extension |

Three more sit under **SpecKit Companion** and belong to the [Workflow Builder](/docs/customize/workflow-builder): **Open Workflow Builder**, **Preview Pipeline Build** and **Build Pipeline from companion.yml**.
