There are two installs and they go through different channels. The VS Code extension comes from the Marketplace. The Companion Spec Kit extension comes from the `specify` CLI, which is where the prerequisite below bites.

## Before you start

| You need | Why |
| --- | --- |
| VS Code, or an editor that reads the Open VSX registry | The viewer, the sidebar and the review comments are a VS Code extension. |
| A folder open as a workspace | Specs are read from the folder you have open. With no folder, the sidebar shows an empty state and an **Open Folder** action. |
| A `specify` CLI that has the `extension` subsystem, at Spec Kit 0.9.5 or newer | Step 2 covers this. It is the one prerequisite people skip, and skipping it makes step 3 fail with an error that doesn't say why. |

<GuidedStep n={2} title="Get an extension-capable Spec Kit CLI">

The `specify extension` subsystem ships in the GitHub-source build of Spec Kit. The stock PyPI `specify-cli` package exposes `init`, `check` and `version` only, so step 3 fails on it with `No such command 'extension'`.

Installing from source is a global change to your `uv` tools, not a project-local one.

<div slot="action">
  <CodeLine command={SOURCE_CLI} />
</div>

<div slot="result">

`specify extension --help` lists `add` and `list`. If it doesn't, step 3 has nothing to run and you're still on the stock package.

</div>

</GuidedStep>

## Updating

Re-run the exact same command from step 3. The `companion-latest/companion.zip` URL is a rolling asset that always serves the newest build, and `--force` refreshes an existing install in place. There's no version string to edit and no new URL to find.

Inside the editor there are two paths to the same result. The Specs view's **More Actions** menu has an **Install Companion Extension** entry, and its **Upgrade…** submenu has **Update spec-kit Extension**. Either runs `specify extension add companion --from <URL>` in a terminal for you, adding `--force` when the extension is already there — `extension add` refuses to overwrite an existing install without it.

The extension also nudges you toward this install on its own: a toast on activation when the project has a `.specify` folder but no Companion, a pinned row at the top of the Specs view, and a one-click prompt when you pick the Companion workflow without it. Set `speckit.companion.installPrompt` to `false` to turn all of them off, or choose **Don't show again** on the toast.

## When something didn't take

**`No such command 'extension'`.** The `specify` on your path is the stock PyPI build, which has no extension subsystem at all. Go back to step 2 and reinstall from source, then re-run step 3.

**It says `companion` is already installed, or you're stuck on an old build.** The command in step 3 already carries `--force`, which is what refreshes an existing install. If it still won't move, run `specify extension remove companion` and add it again.

**The `/speckit.companion.*` commands aren't showing up.** Confirm the install landed in this project: run `specify extension list` from the repo root, not from your home directory. Then reload the window, or restart the CLI, so your provider re-reads its command directory.

**Only two views in the sidebar.** That's the expected shape before step 3, and Settings & Feedback stays hidden until you set `speckit.views.settings.visible`. If Living Specs is still missing after a successful step 3, the install went somewhere other than this workspace.
