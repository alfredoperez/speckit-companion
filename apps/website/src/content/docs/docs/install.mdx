export const COMPANION_COMMAND = 'specify extension add companion --from https://github.com/alfredoperez/speckit-companion/releases/download/companion-latest/companion.zip --force';

export const SOURCE_CLI = 'uv tool install specify-cli --from git+https://github.com/github/spec-kit.git --force';

SpecKit Companion comes in two halves: the VS Code extension from the Marketplace, and the Companion Spec Kit extension from the `specify` command. Install them in this order, with a folder open as your workspace. The second half needs Spec Kit 0.9.5 or newer.

## The VS Code extension

<Actions>
  <Button href={MARKETPLACE} external size="md" data-analytics="install_click_vscode" data-analytics-placement="install">Get it on the Marketplace</Button>
  <p>Or from a terminal:</p>
  <CodeLine command="code --install-extension alfredoperez.speckit-companion" />
</Actions>

This is the half you look at. It works on its own, and it is on Open VSX too.

<YouSee>

A SpecKit icon in the activity bar with two views, **Specs** and **Steering**. Two is correct. Living Specs arrives with the second half.

</YouSee>

## A Spec Kit CLI that has extensions

<Actions>
  <CodeLine command={SOURCE_CLI} />
</Actions>

The stock PyPI `specify-cli` has no `extension` command, so the next install would fail. This installs the GitHub build instead. It changes your global `uv` tools.

<YouSee>

`specify extension --help` lists `add` and `list`.

</YouSee>

## The Companion Spec Kit extension

<Actions>
  <CodeLine command={COMPANION_COMMAND} data-analytics="install_click_speckit_copy" data-analytics-placement="install" />
</Actions>

Run it from your project root and copy it whole. The short catalog form does not work. This half writes the run record, a `.spec-context.json` file next to each spec. Without it a spec still renders, but nothing records what the run did.

<YouSee>

A one-time **untrusted source** prompt, because the archive comes from a URL and not the catalog. Accept it.

</YouSee>

## Update later

Run the Companion Spec Kit extension command again. The URL always serves the newest build, and `--force` refreshes in place. To silence the install prompts, set `speckit.companion.installPrompt` to `false`.

## If something did not work

| What you see | What to do |
| --- | --- |
| `No such command 'extension'` | You have the stock PyPI build. Install the GitHub build of the CLI, then add the extension again. |
| Stuck on an old build | Run `specify extension remove companion`, then add it again. |
| No `/speckit.companion.*` commands | Run `specify extension list` from the repo root, not your home directory. Then reload the window so your assistant re-reads its commands. |
| No Living Specs view | The install went somewhere other than this workspace. Run it again from this project's root. |

## Working outside VS Code

| Where you work | What to install |
| --- | --- |
| GitHub Copilot app | Skip the VS Code extension. Add the Companion Spec Kit extension so the board can run the `/speckit.companion.*` commands, then follow [Install the board in the Copilot app](/docs/copilot-app/install). |
| Claude Code terminal | Add the mod in [Install the Claude Code mod](/docs/claude-code/install). It keeps the run in view above the prompt. |
