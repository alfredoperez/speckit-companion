Choose the set of steps each spec goes through. That set is a **workflow**, also called a pipeline. You choose it once, when you create the spec. It is recorded on the spec, and the viewer rail, the sidebar and the footer's forward button all read it from there. It is a per-spec decision, not a global mode.

<MediaSlot
  feature="own-workflow"
  caption="The workflow is recorded when the spec is created. Every rail, document list and dispatch afterwards comes from that recording."
/>

Open **SpecKit: New Spec**. The **Workflow** choice in the panel is the whole decision, and it comes pre-selected.

## The two that ship

| Workflow | Steps |
| --- | --- |
| SpecKit | specify, plan, tasks, implement |
| SpecKit Companion | specify, plan, tasks, implement, mark-complete |

**Companion closes its own specs.** Stock SpecKit ends at implement and leaves the spec at Implemented until you press Mark Completed. Companion's last step marks it complete as part of the run.

**Companion's commands write less.** They skip sections a typical change never needs and size the ceremony to the change. Stock commands stay installed either way. This is a choice between two command families.

To see a whole Companion run in one picture, read [One run, start to finish](/docs#one-run-start-to-finish).

## Set the default

```json
{ "speckit.defaultWorkflow": "companion" }
```

This decides what Create New Spec pre-selects, nothing else. It does not restrict your choice and does not change existing specs. Only a value you set is honored. Unset, installing the Companion Spec Kit extension is enough to pre-select Companion. See [Configuration](/docs/reference/configuration#workflow-choice).

## Without the Companion extension

Companion still appears in the panel, marked **Install to enable**. If you dispatch a Companion step anyway, the four workflow commands fall back to their stock twins with an install prompt. Commands with no stock twin, such as mark-complete, are suppressed.

## The Auto button

When the workflow supports it (Companion does), the panel shows **Auto**. It sends `/speckit.companion.auto`, which runs specify through mark-complete without pauses. It needs the Companion Spec Kit extension. It is one command your assistant follows, so the editor shows no progress bar and cannot pause it.

## Define your own

There is no workflow editor. You write it in settings. This is the smallest valid workflow:

```json
{
  "speckit.customWorkflows": [
    {
      "name": "my-workflow",
      "displayName": "My Workflow",
      "steps": [
        { "name": "specify",   "label": "Specify",   "command": "myflow.specify",   "file": "spec.md" },
        { "name": "plan",      "label": "Design",    "command": "myflow.plan",      "file": "design.md" },
        { "name": "tasks",     "label": "Tasks",     "command": "myflow.tasks",     "file": "tasks.md" },
        { "name": "implement", "label": "Implement", "command": "myflow.implement", "actionOnly": true }
      ]
    }
  ]
}
```

`name` is what gets recorded on a spec. `displayName` is the picker label. Each step has a `command` (no leading slash needed), a `label` for the rail and footer, and a `file` it produces. Set `actionOnly` when the step writes no document, as Implement usually does.

Your workflow appears next to the two built-ins. The sidebar and rail show your step names as you wrote them, so a workflow with Design and Review steps shows Design and Review.
