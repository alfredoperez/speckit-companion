The Overview shows what a run did, on one page: why the spec exists, how long each phase took, what was checked, what was decided and which requirement got which test. It is read from the **run record**, a `.spec-context.json` file next to the spec. Nothing on the page runs or re-checks anything.

It appears for a regular feature spec whose run recorded something. A status, a current step or your own review comments don't count, so a spec that was never run opens on its document instead. A living spec has its own overview. The `speckit.viewer.activityPanel` setting, on by default, turns the page off. A region with nothing recorded doesn't render, so a thin page means a thin record.

## The tour

Each region has a small kicker, a title and, on the right, a count. Skim the counts first: they tell you where to read closely.

1. **Intent.** The one sentence the run answers to. Beside it: the approach, the working area, a sizing line such as `Sized simple: 6 files, 8 tasks projected`, and any living specs the run loaded.
2. **Run overview.** One entry per phase with the time it took, and the run's total as active time. The waits between steps count toward neither.
3. **Expectations.** Constraints on one side, declared non-goals on the other.
4. **Verified.** Each check, the command the assistant said it ran, and the outcome it reported.
5. **Decisions.** The choice, why, and what was rejected.
6. **Coverage.** Requirement, the tasks that delivered it, the tests that exercise it.
7. **Run log.** Collapsed: the per-phase timeline, per-task records, concerns, files touched, review comments.

## What each region tells you

**Intent.** Read it first. If it doesn't match what you expected, stop there. Living specs are the durable specs for one capability of the codebase, listed as links.

**Run overview.** A blank duration is not a bug or a zero. It means the page declined to guess. The head then reads "Timing coverage: N of M phases", or "Timing not recorded". A phase can read "folded into Plan" when the run merged it into an earlier one. A running phase has no end yet, and its live timer is on the rail tab.

**Expectations.** Something you expected isn't in the diff? Check the non-goals before calling it a gap.

**Verified.** The count reads `3 passed`, or `2 passed · 1 warned` when the run reported benign warnings. This is a report, not a re-run. A green row means the assistant said it passed. Use it to learn which commands to run yourself.

**Decisions.** The first three show and the rest sit behind "Show N more decisions". The rejected line is the useful part: it is what a future session would otherwise rediscover the slow way.

**Coverage.** The table most often carries bad news. Untraced requirements sort first, and six rows show before "Show all N requirements". The count reads `4/7 traced`, in a warning tone until every requirement has evidence. Evidence takes four forms: "N tests", "No test linked", "N tests not found", and "K of N found". The check is that the file exists. Nothing runs the test.

**Run log.** Open it when you need to know which files a run touched or what one task did.

## Good to know

- **Where it comes from.** The page is read out of `.spec-context.json` next to the spec. The Companion Spec Kit extension writes it during runs, the VS Code extension only reads it, and the two install independently. Commit the file and the record travels with the branch.
- **Without the Companion extension**, a banner offers to install it, and the page will be thin because most of what it reads never gets written. Dismiss it once and it stays gone, or set `speckit.companion.installPrompt` to `false`.
- **Timestamps differ in trust.** Step boundaries and per-task finishes are written by a script. Clarify and analyze closes, and plan and tasks substeps, are reported by the assistant to the second. The run only says "X active", the time its phases took without the waits between them, when specify, plan, tasks and implement all measured cleanly.
- **The log only grows.** A write that would publish a shorter history is rejected.
