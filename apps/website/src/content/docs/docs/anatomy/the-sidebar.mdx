A fresh install shows Specs and Steering. Living Specs appears with the Companion Spec Kit extension. Settings & Feedback stays hidden until you turn on `speckit.views.settings.visible`.

## Specs

  feature="specs-sidebar"

/>

<MediaSlot
  feature="live-sidebar-hover"
  caption="Hover a spec to get its Run and More actions buttons."
/>

1. **Toolbar.** Refresh, Filter, Sort, Collapse All or Expand All, Open Pipeline Builder and New Spec. Pipeline Builder needs the Companion Spec Kit extension.
2. **Groups.** **Active**, **Completed** and **Archived**, each with a count. Empty groups are hidden.
3. **Spec row.** The name comes from the folder, so `515-readable-spec-names` reads "Readable Spec Names". Click the name to open the viewer. Click the chevron to only expand.
4. **Description line.** For a spec in flight, the last finished task and how long ago anything happened, like `T004 · 22h ago`. A spec you ran from Companion also names the assistant its last step went to, like `T004 · 22h ago · Claude Code`.
5. **Document rows.** One per document, each with its own mark.
6. **Hover actions.** **Resume** when it applies, and **More Actions…**. Right-click opens the same menu.

**What the spec icon says**

| Icon | Meaning |
| --- | --- |
| Plain beaker | Created, nothing recorded yet |
| Blue beaker | A workflow step is current |
| Yellow beaker | Implement finished, and you have not confirmed |
| Green beaker | You marked it complete |
| Spinner | A step is running now |

**What a document mark says**

| Mark | Meaning |
| --- | --- |
| Green check | Done, and the file has real content |
| Blue dot | In progress |
| Hollow circle | The file exists and the workflow has not reached it |
| `not created` | The file is not on disk yet |

**Resume** finds where the spec stopped and sends one command to your assistant. It needs the Companion Spec Kit extension. **More Actions…** offers Mark Complete, Archive, Reactivate, copy and reveal actions, and Delete. **Set Status…** is the way out for a spec the buttons will not move. **Show Terminal** appears while the terminal Companion opened for the spec is still open, and brings it to the front.

### Bug reports

Spec Kit's bug extension (`specify extension add bug`) writes an assessment, a fix and a test report for each bug it handles. The Specs view lists them in a **Bugs** group after Archived, which appears only once a report exists. Each row is named by the bug's title and reads the reports it has and the latest outcome, like `assess · fix · test · verified`. Expand it for Assessment, Fix and Test, where a report not written yet reads `not created`. Filter narrows bugs too, and Sort leaves them in name order. Click a bug or a report to read it in the viewer.

## Living Specs

<MediaSlot
  feature="living-specs"
  caption="The Living Specs tree beside a capability open in the viewer. Rows carry a coverage count or a drift warning."
  wide
/>

A **capability** is behavior your code keeps having, and a **living spec** is its lasting spec.

- **Coverage** (`7/9 covered`) counts requirements with recorded evidence. No coverage file means no number, which is not the same as zero.
- **Drift** turns the icon to the warning color when source files changed after the spec was last committed.
- **Toolbar.** Refresh, Adopt Code Area and Sync. Right-click a row to check drift or coverage.

Without a `living-specs.yml` at the repo root, the view says "Living Specs are off". [Living specs](/docs/discussions/living-specs) explains how to turn them on.

## Steering

A steering document is a standing instruction. A spec says what to build this time, and steering says how this project builds anything. The view gathers the files your provider already reads, plus Spec Kit's constitution, scripts and templates. See the [steering guide](/docs/guides/steering).

## Settings & Feedback

Five rows: Pipeline Builder, Open Settings, Report a Bug, Request a Feature and Rate on Marketplace.

## Good to know

- **Empty workspace.** One welcome block offers **Create your first spec** and **Open a live sample**.
- **Install badge.** Without the Companion Spec Kit extension, a dot on the SpecKit icon reads "Install SpecKit Companion". It clears once the extension is present.
- **Upgrades** live in the Command Palette: `SpecKit: Upgrade…`.
- **Which assistant.** The name on a row is the assistant Companion last sent that spec to. A step you type straight into an assistant is not recorded, and neither is the first step of a new spec, which runs before the spec folder exists. Companion cannot jump to a chat panel, because VS Code does not say which panel picked up a command, and it does not mark a spec as waiting for your answer.
- **Several at once.** Shift-click or cmd-click to select specs, then mark, archive or reactivate them together.
