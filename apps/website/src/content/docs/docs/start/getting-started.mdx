Create one spec, run it through its workflow, and read the record it leaves. This picks up after [Install](/docs/install).

<GuidedStep n={1} title="Initialize the workspace">

Open the SpecKit icon in the activity bar. In a project that has not run `specify init`, the Specs view offers **Initialize Workspace**.

<div slot="action">
  <p>Click <strong>Initialize Workspace</strong>.</p>
</div>

<div slot="result">

A **Configure Constitution** prompt and a **Create New Spec** button. Once the constitution is set, the panel offers **Create your first spec** and **Open a live sample**, a finished run you can look at first.

</div>

<MediaSlot
  slot="media"
  feature="specs-sidebar"
  caption="The Specs view is where every step starts, and where each spec shows how far it got."
/>

</GuidedStep>

<GuidedStep n={2} title="Create your first spec">

Click `+` in the Specs view, or run **SpecKit: New Spec** from the command palette. Pick a workflow, describe what you want to build, and go. Not sure which workflow? See [Pick a pipeline](/docs/discussions/pick-a-pipeline).

<div slot="result">

A new spec under **Active**, with its workflow recorded. Expand it to see each document and its state.

</div>

<MediaSlot
  slot="media"
  feature="own-workflow"
  caption="The workflow you pick decides which steps your spec goes through."
/>

</GuidedStep>

<GuidedStep n={3} title="Open it in the viewer">

Click the spec. Its documents open as a page, with the workflow's steps in a rail beside them.

<div slot="result">

Your `spec.md` as a readable page. Hover a line to comment on it.

</div>

<MediaSlot
  slot="media"
  feature="spec-viewer"
  caption="The spec as a page, not a file."
/>

</GuidedStep>

<GuidedStep n={4} title="Run the next step">

The viewer footer has one forward button named for the next step, with `Next: Plan` above it. Click it. It closes the current step, starts the next, and hands that command to your AI provider.

The Companion workflow also has an **Auto** button in the Create New Spec panel. It runs `/speckit.companion.auto`, from specify through mark-complete, without pausing.

If there is no forward button, that is a real state. [The viewer anatomy](/docs/anatomy/anatomy-of-the-spec-viewer) lists the five cases.

<div slot="result">

While a step runs, the buttons drop and the footer says "Step running, actions unlock when it settles". During implement, the step tab shows a live percentage from checked boxes in `tasks.md`.

</div>

<div slot="result">

</div>

## What to know

The extension hands your assistant the command text, then reads what lands on disk. It never reads the chat. The Overview's checks are a recorded report of what the assistant said it ran, and nothing re-executes. Everything is plain files in your repo.
