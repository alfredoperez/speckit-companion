Click `+` in the Specs view, or run **SpecKit: New Spec** from the command palette. If there is no SpecKit icon in the activity bar yet, [install](/docs/install) first.

## Create the spec

The panel asks how the spec should run before it asks what to build:

<WorkflowChoice />

Then write the brief in a few sentences: the problem, who has it, and what done looks like. A Jira or GitHub link works too, and you can attach an image.

<DocFigure src="live-create-spec.png" recapture caption="Workflow first, then the brief. Auto sits beside Create Spec." />

Press <kbd>Cmd</kbd> + <kbd>Enter</kbd> (<kbd>Ctrl</kbd> + <kbd>Enter</kbd> on Windows and Linux) or click **Create Spec**. The new spec is listed under **Active** in the Specs view.

## Let specify run

**Create Spec** sends the specify command to your assistant, in its terminal or its chat. Companion doesn't read that conversation. It watches the spec folder, so the viewer changes only when a file does.

<YouSee>

While it runs, the viewer footer reads **Step running, actions unlock when it settles**. When it settles, **Specification** is checked in the rail, and Plan and Tasks stay hollow until their documents exist.

</YouSee>

<DocFigure src="run-in-flight-x16x9.png" caption="After specify: Specification is checked, and Plan and Tasks wait for their documents." />

With the SpecKit Companion workflow, a small change gets its plan and task list in the same pass, so Plan and Tasks can be checked already. [Specify](/docs/steps#specify) has the rule it uses to size a change.

## Read it

Click the spec's name in the sidebar and it opens as a page: user stories, requirements and success criteria, with the workflow's steps in a rail beside them. [Viewer and sidebar](/docs/navigate/viewer-and-sidebar) covers the rest of what's on screen.

This is the cheapest moment to correct the spec, because nothing has been planned from it yet. Hover a line, leave a comment, and send them all to your assistant at once. [Review with comments](/docs/steps/review-with-comments) shows how.

## Move to the next step

The footer names the next step, **Next: Plan**, above a **Plan** button. Press it and Companion sends the plan command the same way it sent specify. After a small change that was planned in the first pass, the footer reads **Next: Implement**.

The button is only there when the step you're reading is the run's current one and nothing is running. Clicking another tab in the rail changes what you read and never moves the run.

Tasks and implement work the same way, one button at a time. Once the build is done the footer offers **Converge**, which checks the code against the spec and adds tasks for anything missing.
