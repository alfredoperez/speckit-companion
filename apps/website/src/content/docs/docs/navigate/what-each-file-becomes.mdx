The viewer reads the markdown Spec Kit writes and draws each known part as a card. You write nothing special. A part the viewer can't read stays plain markdown, so the file still reads the same on GitHub.

## spec.md

| In the markdown | In the viewer |
| --- | --- |
| `### User Story 1 - Title (Priority: P1)` | A story card: its id, priority, why it matters, how to test it alone, and the tasks that build it |
| `**Acceptance Scenarios**:` and a numbered list of Given, When, Then | Scenario rows, each keyword in its own column |
| `- **FR-001**: System MUST …` | A requirement row: the id, the rule with MUST in bold, and Covered or Untested once tasks exist |
| `- **SC-001**: …` | A success criterion row, its numbers in bold |
| Edge Cases, Assumptions, Key Entities | Short lists, each item on its own row |
| `## Clarifications` | The questions asked and the answers given, folded |

## plan.md

| In the markdown | In the viewer |
| --- | --- |
| `## Summary` | The first sentence large, with the file count and the gate result under it |
| `## Technical Context` | A grid of facts. A NEEDS CLARIFICATION value shows as open. |
| `## Constitution Check` | One row per gate, marked pass, fail or justified |
| `## Project Structure` | A file tree, each file marked new or changed |
| A ` ```calls ` block | Call paths: the functions a change reaches, new rows green and changed rows amber |
| A ` ```states ` block | Lifecycle states you click through, with the arrows between them |
| A ` ```screen ` block | A rough sketch of the screen |

The last three are [plan blocks](/docs/steps/plan-blocks). That page has the grammar of each.

## tasks.md

| In the markdown | In the viewer |
| --- | --- |
| The whole file | A header with tasks done, one bar for every task, and a filter by story |
| `## Phase 3: User Story 1 … (P1)` | A phase with its progress bar and count. A finished phase folds shut. |
| `- [ ] T012 [P] [US1] Do the thing in src/file.ts` | A task row: the id, `[P]` and the story as chips, the file as a link |
| `**Checkpoint**: …` | What the phase must prove, and how many tasks are left before it can |

## research.md

| In the markdown | In the viewer |
| --- | --- |
| A `## Decision 1: Title` section, or a section with `**Decision**:` | A decision card: the pick, and why |
| `**Alternatives considered**:` | The options turned down, each with the reason, folded under the card |
| Every decision in the file | A Decisions at a glance list at the top |
