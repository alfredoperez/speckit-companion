See and manage the standing rules your AI follows, in one view. A spec says what to build this time. A **steering document** says how this project builds anything: conventions, architecture, testing habits.

Your AI provider, the assistant you chose in `speckit.aiProvider`, already has a place for those. Claude Code reads `CLAUDE.md`, Codex and OpenCode read `AGENTS.md`, and the others have their own filenames. The [provider matrix](/docs/reference/providers) lists every path. The Steering view adds no new format. It gathers what your provider already reads.

## What the view shows

Two scopes run through it. **Project** is this repository. **User** is you, on this machine, across every project.

| Section | When it shows |
| --- | --- |
| Companion | Only when the Companion Spec Kit extension is installed |
| Your provider | Always. Holds Project and User groups for the rule file, Agents, Skills and Settings. |
| Steering Docs | Only when your provider has a steering directory with at least one document |
| SpecKit Project Files | Only when a constitution, script or template exists |
| References | Only when a custom workflow declares reference folders that exist |

A missing section means that thing does not exist in this project yet. With IDE Chat there is no provider-owned configuration, so the provider sections are empty.

## The extension does not read them

Nothing under Steering is read when a step is dispatched. The command carries the spec, not your rules. Your provider reads its own file on its own, so a rule that is ignored is a provider question. The view can show you `CLAUDE.md`. It cannot make the assistant follow it.

## What you can do

Every action builds a prompt and hands it to your provider.

| Action | What happens |
| --- | --- |
| **New Steering Document** | Your AI writes a markdown file into the steering directory |
| **Refine** | Your AI improves the document in place |
| **Delete Steering** | The file is removed, then your AI cleans up references to it |
| **Create Project Rule** / **Create User Rule** | Creates or opens your provider's own rule file, named as it really is (for example `GEMINI.md`) |

Refine and Delete appear only on Steering Docs and References. Provider and Spec Kit files can be opened and revealed, never deleted from the tree.

## The Companion node

With the Companion Spec Kit extension installed, a Companion node comes first. **Configuration** opens `.specify/companion.yml` (see [Custom commands and hooks](/docs/guides/customize)). **Commands** lists the `/speckit.companion.*` set from the installed manifest. **Templates** lists the extension's markdown templates and is hidden when there are none.
