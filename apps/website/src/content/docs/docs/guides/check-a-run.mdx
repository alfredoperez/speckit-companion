Three commands answer three questions about a spec: where is it, how do I carry on, and did the run do what it says. All three need the [Companion Spec Kit extension](/docs/install) and work with any provider.

| Question | Command | What it does |
| --- | --- | --- |
| Where does this spec stand? | `/speckit.companion.status` | Reports the current step, its status, the decisions recorded so far and the next action. Changes nothing. |
| I stopped halfway. How do I carry on? | `/speckit.companion.resume` | Finds the next step, carries the recorded decisions into scope and sends that step's command. In implement it continues at the next unchecked task. |
| Did the run do what it says it did? | `/speckit.companion.doctor` | Recomputes what happened and reports problems. Read-only, and it never stops your work. |

## Resume from the sidebar

Hover a spec that is still in flight and click the play button. That is **Resume**. It shows only when the spec can move forward and the Companion extension is installed.

## Run the doctor

Type `/speckit.companion.doctor` in your assistant. With no argument it checks the active spec. Name one with `--feature-dir specs/042-export-csv`, or check every spec with `--all`.

It looks for the things a run can get wrong without anyone noticing:

- **Unfinished work.** A step that started and never finished, or a task ticked in `tasks.md` with nothing recorded for it.
- **A step doing the next step's work.** Plan content in the spec, a task list in the plan, code written before implement.
- **A step that closed having verified nothing.** Implement finished but no test or check ever ran.
- **A missing file.** A step that closed without the document it promised.
- **Why a spec did not complete.** The write was refused, it never arrived, or it landed and the display disagrees.

Every check says whether it ran, was skipped (with the reason) or does not apply, so a check that could not look never reads as clean. The doctor reports and stops: fixing what it finds is your call.

## Good to know

- Add `--json` for a machine-readable report, or `--chat` to also read the AI session transcript for the run and explain failed or abandoned work.
- Every capture call writes one line to `specs/<NNN>/.trace.jsonl`, which is what the doctor reads to explain a failed capture.
