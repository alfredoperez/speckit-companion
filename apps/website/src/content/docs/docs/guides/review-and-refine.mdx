Comment on a spec line by line, then send every pending comment to your AI in one prompt. Open a spec in the viewer and hover any line. Click the comment button that appears, type, and the card pins under that line.

## Comment on a line

The composer knows what kind of line you are on (user story, task, section, scenario or paragraph) and offers matching quick actions. Most just fill in suggested wording. On a task line, **Toggle** also flips the task's checkbox.

You can comment on paragraphs, headings, list items, tasks, blockquotes, requirement rows and acceptance scenarios. Code blocks, tables and Mermaid diagrams have no line to attach to, so comment on the heading or paragraph above them.

A card starts collapsed and reads **Pending** or **Applied**. Expanded, it offers:

| Action | When |
| --- | --- |
| **Refine** | While the comment is pending. Sends every pending comment on the document. |
| **Edit** | Any time the spec is active. Keeps the id, anchor and status. |
| **Delete** | Any time the spec is active. Removes the comment from the record. |

## Comments stay in the repo

A comment is written to `.spec-context.json` in the spec's folder. Commit it and the review travels with the branch.

- Comments written quickly never overwrite each other.
- Reopening the tab re-anchors each comment onto the page once, never twice.
- Anchoring follows the block of text, not a line number. If the block is edited away, the comment stays listed with its status in the Activity list under Run log.

## Send the pending comments

<MediaSlot
  feature="review"
  caption="Refine turns every pending comment into one prompt, each with its line, section heading and source text."
/>

The footer button reads **Refine (N)** once N comments are pending, and is hidden when none are. Pressing it, or Refine on any card, does the same thing.

- **Current document only.** Comments on the plan do not ride along with the spec.
- **Context included.** Each comment names its line and section, quotes the source block, then gives your text.
- **An edit, not a rewrite.** The prompt asks the AI to edit that file in place.

The prompt goes to your configured provider: a terminal CLI, an IDE chat or the Claude Code panel.

## Applied means sent, not checked

After the prompt is handed over, the comments flip to **Applied** and stay as history. That records that they were sent. The extension never reads the file back, so read the diff yourself, then comment again on anything missed.

On completed or archived specs, cards stay readable but Refine, Edit and Delete are gone.

## If a comment goes missing

- **A comment did not save.** The write is skipped when the run record is missing or unreadable. The viewer creates it on first open, so check the spec folder.
- **A comment vanished after an edit.** Look for it in the Activity list under Run log.
