Assessment answers "is this worth building?" before the spec steps answer "how do we build it?". It is Spec Kit's own process, separate from specify, plan and tasks. You enter it on purpose, and it never changes source code. The input is just an idea: pasted text, a URL, a ticket, or a pointer at code that already exists.

## The five stages

You run each one in your assistant, in order, usually once.

| Command | What it does | Writes |
| --- | --- | --- |
| `/speckit.assess.intake` | Captures the raw idea | `intake.md` |
| `/speckit.assess.research` | Gathers evidence about users, the market and prior art, including evidence against the idea | `research.md` |
| `/speckit.assess.define` | Defines the problem: users, goals, non-goals, success metrics and the cost of doing nothing | `problem.md` |
| `/speckit.assess.shape` | Shapes two or three options with their size and trade-offs, and recommends one or none | `concept.md` |
| `/speckit.assess.decide` | Scores the idea and gives the verdict | `decision.md` |

Name the idea once and reuse the name, for example `/speckit.assess.intake "Let users work offline" slug=offline-mode`, then `/speckit.assess.research slug=offline-mode`.

The order is not rigid. Define can run straight from your input, without intake or research. Shape and decide both need `problem.md`.

## What it writes

Each idea gets its own folder, `.specify/assessments/<slug>/`, with one markdown file per stage. The commands write only there.

## The verdict

| Verdict | What it means | What you do next |
| --- | --- | --- |
| **go** | The problem is valid, the evidence is adequate and a concept is shaped | Hand the summary in `decision.md` to `/speckit.specify` yourself. See [Specify](/docs/steps/specify). |
| **needs-clarification** | Something is missing. A go without a shaped concept is downgraded to this. | Fill the gap in the file that has it, by editing it or asking your assistant, then have the decision revised. You do not rerun the stage. |
| **kill** | Not worth building | Nothing. The reason is on record, which is a good outcome. |

Most ideas should be killed or parked before shape.

## In SpecKit Companion

<YouSee>

An **Ideas** pane under Specs. **Assessing** lists the ideas still in progress with the stage they reached, and **Decided** lists the rest with the verdict. Expand an idea for its five stage documents and click one to read it in the viewer. A stage not written yet reads `not created`.

</YouSee>

Companion reads the files and starts nothing: you run the assess commands in your assistant. Before the assess extension is installed the pane holds one row that installs it.

Once a go becomes a spec through `/speckit.specify`, that spec shows up in the Specs view like any other.
