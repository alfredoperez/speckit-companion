There is no separate command for sizing up an idea. You run [Specify](/docs/steps/specify) on it and stop there. A spec costs minutes and no code, and it tells you most of what you need to decide.

## What one specify run tells you

| You want to know | Where to look |
| --- | --- |
| How big is it? | The sizing line on [the Overview](/docs/results/the-overview), such as `Sized simple: 6 files, 8 tasks projected`. The Companion workflow writes it. |
| What is still unclear? | The open questions the spec marks in its own text |
| What would done look like? | The acceptance scenarios and success criteria in the spec |
| Does it touch something that already has a spec? | The living specs listed beside the intent on the Overview, when [living specs](/docs/results/living-specs) are on |

## Dig further without building

These are Spec Kit's own commands. Each sits under **Other actions** in the viewer footer, on the tab it is about.

| Action | Tab | What it does |
| --- | --- | --- |
| **Clarify** | Specification | Asks you questions to settle what the spec left open |
| **Checklist** | Plan | Generates a quality checklist for the plan |
| **Analyze** | Tasks | Cross-checks the spec, the plan and the tasks for consistency |

## If the answer is no

Leave the spec where it is, or shelve it: hover it in the sidebar, open **More Actions…** and choose **Archive**. It moves to the Archived group and can be reactivated later.
