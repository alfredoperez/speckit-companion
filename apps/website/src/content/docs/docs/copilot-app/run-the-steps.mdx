---
title: Run the steps from the board
description: Which commands the board's buttons send into the GitHub Copilot app chat, and what the board does and does not do by itself.
---

Each button on the board sends one command into the chat, and your agent runs the step from there.

## Which commands the buttons send

| The project and the spec | The buttons send |
| --- | --- |
| The [Companion Spec Kit extension](/docs/install) is installed | `/speckit.companion.*` |
| It is not installed | The stock `/speckit.plan`, `/speckit.tasks` and `/speckit.implement` |
| The spec was started with the Spec Kit workflow | The stock commands, even where Companion is installed |

A spec keeps the workflow it was started with, so a run never switches halfway. The board says which commands it is using under the next-step button.

## What lands in the chat

A button sends two things: the command, and one sentence telling the agent to read its run instructions from a file. The instructions themselves, which tell the agent how to record the run, are written to `.speckit-companion/prompts/` in the project, so the chat stays short. That folder is ignored by git.

After a send, a note at the bottom of the board shows the message that was sent, with **Show prompt**, **Copy** and the path of the instructions file.

## When Companion is not installed

The board still works with stock Spec Kit, and it says so in one line on the New spec form and on the next-step card. **Install it** shows the install command with a Copy button, and **Ask Copilot to install it** asks the agent to run it for you. Dismiss the line and it stays hidden for the session.

## Good to know

- **The board never edits a spec.** It does not touch `.spec-context.json` or any spec file; the commands it sends do that. The only files it writes are its own run instructions under `.speckit-companion/prompts/`.
- **You can ask the agent.** "Which specs are still open?" or "show me the export spec", and the board follows.
