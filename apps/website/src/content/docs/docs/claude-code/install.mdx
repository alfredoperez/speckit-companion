If you run the Spec Kit commands in Claude Code, the mod keeps the run in view while you work. It shows the same steps, times and task counts as the VS Code viewer and the [Copilot app board](/docs/copilot-app/navigate-the-board). You do not need the VS Code extension for this path. The mod draws in the Claude Code terminal and in the Code tab of the Claude Desktop app.

The path has the same shape everywhere: Spec Kit itself, then the Companion extension for Spec Kit, which is optional but recommended, then the one thing your tool needs. [Install where you work](/docs/install) has the other two places.

<Steps>

1. <span id="claude-spec-kit"></span>**Get Spec Kit**

   Spec Kit is GitHub's toolkit for spec-driven development. Its `specify` command sets a project up with the `/speckit` commands Claude Code runs.

   <Actions>
     <CodeLine command={SOURCE_CLI} />
   </Actions>

   This installs the GitHub build. The stock PyPI `specify-cli` has no `extension` command, so step 2 would fail with it. The command changes your global `uv` tools.

   Then set the project up for Claude Code, from its root:

   <Actions>
     <CodeLine command="specify init --here --integration claude" />
   </Actions>

   <YouSee label="You should see">

   A `.specify` folder in the project, and `/speckit-specify` among the commands Claude Code offers.

   </YouSee>

2. <span id="claude-companion"></span>**Add the Companion extension for Spec Kit** (optional, recommended)

   This is the engine half. It records each run, adds the Companion pipeline and Auto, and brings living specs. It needs Spec Kit 0.9.5 or newer.

   <Actions>
     <CodeLine command={COMPANION_COMMAND} data-analytics="install_click_speckit_copy" data-analytics-placement="install" />
   </Actions>

   Run it from your project root and copy it whole.

   **Without it** the mod still follows your run, from the files alone. Each step says when its document was last written, where a recorded run shows how long the step took. The Overview tab shows what the spec says, not what the run decided and checked.

   <YouSee label="You should see">

   A one-time **untrusted source** prompt. Accept it. Then Claude Code offers `/speckit-companion-specify` next to `/speckit-specify`.

   </YouSee>

3. <span id="claude-mod"></span>**Add the mod**

   You need Claude Code 2.1.287 or later. Check with `claude --version`.

   <Actions>
     <CodeLine command="claude plugin marketplace add https://speckit-companion.dev/plugins/marketplace.json" />
     <CodeLine command="claude plugin install speckit-companion@speckit-companion" />
     <p>In a session that is already open, load it with:</p>
     <CodeLine command="/reload-plugins" prompt={false} />
     <p>Then open the pane and pick the spec to follow:</p>
     <CodeLine command="/speckit-tracker" prompt={false} />
   </Actions>

   <YouSee label="You should see">

   Run `/plugin`. The line under the tabs lists `speckit-companion` among the active mods. `/speckit-tracker` opens the pane on its Specs tab.

   </YouSee>

4. <span id="claude-check"></span>**Check that it took**

   Type `/speckit-companion-specify` and a small change you want. On stock Spec Kit, type `/speckit-specify`.

   <YouSee label="You should see">

   A line above the prompt naming the spec. In the pane, Specify is ticked when the turn ends, and the last line names the next command.

   </YouSee>

   <DocFigure
     src="live-mod-run.png"
     alt="The mod's pane during an implement run: Specify, Plan and Tasks ticked with their times, Implement running, the documents, and three of six tasks ticked."
     caption="The pane a few steps later: each step with its time, the documents and the tasks."
   />

   [A run, step by step](/docs/claude-code/a-run-step-by-step) follows one spec from specify to implement.

</Steps>

If nothing shows, run `/reload-plugins`, then widen the terminal or run `/speckit-tracker`. The pane opens by itself only in a wide terminal.
