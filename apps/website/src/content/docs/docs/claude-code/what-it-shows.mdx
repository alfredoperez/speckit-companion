The mod adds two things to Claude Code, a band and a pane, and both follow one spec at a time.

## What you get

| Part | What it shows |
| --- | --- |
| A band above the prompt | The spec you are following and where its run stands, such as `042-export-csv · Plan done · Tasks 7/12 · Implement running` |
| A pane beside the transcript | The four steps with the time each one took, the total active time, and the task list by phase with the task in flight marked. Tasks tick off as the agent finishes them. |

Step times follow the same rules as the viewer. A step ends at its own finish, the waits between steps count toward nothing, and the total is the time the steps were actually running.

## Where it shows

| Where you run Claude Code | What you see |
| --- | --- |
| A terminal at least 144 columns wide | The band, and the pane beside the transcript by itself |
| A narrower terminal | The band. The pane waits until you run `/speckit-tracker`, then sits above the prompt. |
| The Code tab of the Claude Desktop app | The band and the pane |
| The VS Code extension's chat panel, or `claude -p` | Nothing a mod draws. `/speckit-tracker` answers in text: the spec you are following, its band line, and the recent specs. |

In VS Code itself, the SpecKit Companion extension already shows all of this.

## Good to know

The mod only reads. It never writes a spec file or sends a prompt, so you still run `/speckit-companion-plan`, `/speckit-implement` and the rest yourself.

## Open a step's document

In the pane's **Run** view each step is something you can move to and press. Pressing one opens its document inside the pane: the spec for Specify, the plan for Plan, the task list for Tasks and Implement. Press `b` to go back. A step whose document is not written yet says so and cannot be opened.

A small change that Specify plans and tasks in one pass shows **with Specify** beside Plan and Tasks where a time would be.

## The Overview tab

The pane has three tabs, switched with `1`, `2` and `3`: **Run**, **Overview** and **Specs**. Overview shows what the run recorded about itself: the intent, the approach, what was left out of scope, the decisions and why, what was verified, any concerns, and how many requirements have tests. Each part shows only when the run recorded it.
