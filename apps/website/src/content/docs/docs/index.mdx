SpecKit Companion lets you read, review and track your specs in VS Code. A **spec** is a markdown file that describes what to build before your AI assistant builds it. [Spec Kit](https://github.com/github/spec-kit), the open source tool behind the `specify` command, has your assistant write those files.

## What you get in VS Code

**A spec viewer.** Your `spec.md`, `plan.md` and `tasks.md` open as a page, with a rail down the side for each document.

<MediaSlot
  feature="spec-viewer"
  caption="One spec as a page, with every workflow document one click away."
/>

**Inline review.** Comment on any line. Comments are saved in the spec's own folder.

<MediaSlot
  feature="inline-comments"
  caption="A comment sits on the line it is about, and travels with the spec."
/>

**A Specs sidebar.** Every spec, grouped by where it stands.

<MediaSlot
  feature="specs-sidebar"
  caption="Active and Completed specs, with the state of each document inside."
/>

A **Steering** view also lists the standing instruction files your AI provider already reads.

## What the Companion Spec Kit extension adds

This is a second piece that you install separately with the `specify` command. It records what each step did, how long it took, what it decided and what it checked, in a **run record** next to each spec. The **Overview** in the viewer shows that record.

<MediaSlot
  feature="overview"
  caption="The Overview reads the run record: intent, timing, decisions, checks and coverage."
/>

It also brings the `/speckit.companion.*` commands, a Resume button, a closing `mark-complete` step and Living Specs. A **living spec** is a spec for behavior that outlives any one change.

<MediaSlot
  feature="living-specs"
  caption="Living Specs sit next to the code they describe and flag when the code moves on."
/>

Either half works alone. With only the VS Code extension you get the viewer, comments and sidebar. A spec made without the second half just has less recorded on it.

## One run, start to finish

A Companion run turns a feature request into a spec, a plan, a task list and code. Where a step has several independent pieces, it can hand them to workers. When living specs are on, they are read before the work starts and updated when it ends.

## What it does not do

SpecKit Companion hands your assistant the text of a command, then reads whatever lands on disk. It never reads the chat back, and it gets no signal when your assistant finishes.
