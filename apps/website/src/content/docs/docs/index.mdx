Spec Kit writes your specs as markdown files. SpecKit Companion lets you read, review and track them in VS Code.

<MediaSlot
  feature="readme-hero"

/>

## What you get in VS Code

**A spec viewer.** Your `spec.md`, `plan.md` and `tasks.md` open as a page, with a rail down the side for each document.

<MediaSlot
  feature="spec-viewer"
  caption="One spec as a page, with every workflow document one click away."
/>

**Inline review.** Comment on any line. Comments are saved in the spec's own folder.

<MediaSlot
  feature="inline-comments"
  caption="A comment sits on the line it is about, and travels with the spec."
/>

**A Specs sidebar.** Every spec, grouped by where it stands.

<MediaSlot
  feature="specs-sidebar"
  caption="Active and Completed specs, with the state of each document inside."
/>

There is also a **Steering** view, which lists the standing instruction files your AI provider already reads.

## What the Companion Spec Kit extension adds

A second, separately installed piece. It rides your Spec Kit runs and writes a run record next to each spec: what each step did, how long it took, what it decided and what it checked. The **Overview** in the viewer shows that record.

<MediaSlot
  feature="overview"
  caption="The Overview reads the run record: intent, timing, decisions, checks and coverage."
/>

It also brings the `/speckit.companion.*` commands, a Resume button, a closing `mark-complete` step, and Living Specs.

<MediaSlot
  feature="living-specs"
  caption="Living Specs sit next to the code they describe and flag when the code moves on."
/>

Either half works alone. With only the VS Code extension you get the viewer, comments and sidebar. A spec made without the second half simply has less recorded on it.

## What it does not do

The extension gives your assistant the text of a command, then reads whatever lands on disk. It never reads the chat back and gets no callback when your assistant finishes. Everything you see was written to a file or seen changing on disk.
