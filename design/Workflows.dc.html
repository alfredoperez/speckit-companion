One project, several ways to work
A workflow is a whole named configuration — its node order, its hooks, its template sections, its routing. Switching one is switching all of them at once, so a small fix and a client deliverable can run different pipelines out of the same repository.
Switching does two things
1 Records the choice in .specify/companion.yml under workflow: — so it is committed, reviewed, and the same for everyone on the team.
2 Rebuilds the command bodies, so the assistant reads the new pipeline on its very next run.
Nodes are shared, not copied
Every workflow draws from the same .specify/companion/nodes/. A node you write once can be used by all of them, or by none — which workflow picks it up is the workflow's business, not the node's.
Only one workflow is live at a time. The others sit on disk doing nothing until you switch.
