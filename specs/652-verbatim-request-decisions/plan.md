# Implementation Plan: Keep the request verbatim, and say who decided what

**Spec**: [spec.md](./spec.md) · **Source**: #963 (r5, r6)

## Summary

The run record gains a `request` field, written once from a file or stdin by a new `--request` flag on the writer, so a request with quotes and line breaks never passes through a shell argument. Auto and specify store it the moment their folder exists, and plan is told to read it. Decisions get their own writer path that stamps `by` and `at`, and keys on an optional `id`: a different answer under a known id becomes current and the old one moves into an `earlier` list. The viewer normalizes the new fields once in `pickDecisions` and `deriveViewerState`, and the Overview renders the quoted request and the "answered by" lines.

**Structure Decision**: one writer path per field in `capture.py`, one derivation in `stateDerivation.ts`, and the component reads only the derived state. The shared teamboard fixture stays as it is, so existing captures do not change; new stories carry the new fields.

## Screens

```screen overview Overview, Intent and Decisions
title: Intent
text: Keep the original request word for word
text: Your request, word for word (new) (1)
title: Decisions
row:
  text: 01 Store filters per user
  text: answered by agent · Nov 3, 10:12 (new) (2)
text: A new table, struck through (new) (3)
text: earlier answer · you · Nov 3, 09:58 · reopened (new)
```
1: **Plain text, wraps.** The request keeps its line breaks and never widens the page; a record without one shows no block.
2: **Only when both are known.** A decision with no author or an unreadable time shows no meta, as today.
3: **Oldest first.** Each earlier answer is indented under the current one.
