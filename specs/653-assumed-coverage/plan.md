# Implementation Plan: "Assumed" is a coverage state

**Spec**: [spec.md](./spec.md) · **Source**: #963 (r3)

## Summary

The coverage entry gains an optional `assumes` string. `upsert_coverage` takes it as one more non-destructive slot, `write-context.py` exposes it as `--assumes REQ TEXT`, and the batch `coverage` item accepts `assumes`. Implement's record node, its built command and the GUI preamble tell the agent to record one. The viewer derives `assumes` in `pickCoverage`, and one shared predicate decides whether a row is traced (tested or assumed), so the section count and the header strip cannot disagree. The Coverage row shows an Assumed state in the info colour and the assumption text beneath the requirement.

## Constitution Check

| Principle | Assessment |
|---|---|
| The host owns the filesystem | PASS. `assumes` reaches the webview through `ViewerState`. |
| `.spec-context.json` writers keep its guarantees | PASS. The upsert stays non-destructive under the one lock. |
| Repository text reaches a panel as text | PASS. The assumption renders as a text node. |
| One fact, one derivation | PASS. `isTraced` is the single definition of traced in the webview. |

## Key Decisions

- **One string, replaced on rewrite**, like `title`. A list adds merging rules nobody asked for.
- **Order: untraced, then assumed, then tested.** Gaps lead; an assumed row is accounted for but weaker than a test.
- **A row with missing tests stays missing**, assumption or not, and counts as traced as it does today.
