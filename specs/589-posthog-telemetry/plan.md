# Implementation Plan: Restore Telemetry on PostHog

**Branch**: `589-posthog-telemetry` | **Date**: 2026-08-25 | **Spec**: [spec.md](./spec.md)

## Summary

Replace the dead Azure Application Insights backend inside `TelemetryService` with direct delivery to PostHog's event-capture API, keeping the module's public surface (`sendTelemetryEvent(name, properties)` and the report helpers) byte-for-byte stable so none of the ~20 call sites change. The editor-wide telemetry gate that `@vscode/extension-telemetry` used to provide is re-implemented inside the service with `vscode.env.isTelemetryEnabled` plus a `vscode.env.onDidChangeTelemetryEnabled` subscription, and the common facts the old reporter attached automatically (extension version, VS Code version, platform, anonymized machine id) are re-attached by the service to every event. No new dependency is introduced: events post over the Node runtime's global `fetch`, fire-and-forget, so a dead backend can never surface an error or block a feature. The retired dependency, its committed connection string, its test mock, and the Azure query documentation all go away in the same change.

**Structure Decision**: everything stays inside the existing single-module home (`src/core/telemetry.ts`); the swap is a transport change behind a frozen API, so no new modules or directories are introduced.

## Key risks the design answers

- **The gate promise in `package.json`'s setting description must stay true** — the description tells users the global `telemetry.telemetryLevel` is respected; the cached-listener gate keeps that true without a restart (spec FR-003, SC-003).
- **A committed credential that is write-only** — PostHog project API keys can only ingest, mirroring the old connection-string model (FR-009). The key lands as a constant; until the maintainer creates the PostHog project it stays empty, which (exactly like today) constructs no client and sends nothing.
- **Silent failure is a feature here** — one fire-and-forget POST per event, errors swallowed, no queue and no retries, so quota exhaustion or an outage can never leak into the user experience (FR-011, edge cases).
