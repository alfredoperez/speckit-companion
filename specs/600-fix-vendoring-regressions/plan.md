# Implementation Plan: Fix 0.20.2 Vendoring Regressions

**Branch**: `600-fix-vendoring-regressions` | **Date**: 2026-08-25 | **Spec**: [spec.md](./spec.md)
**Input**: GitHub issue #588

## Summary

Four regressions from the 0.20.2 vendoring pass are restored to their guarded 0.20.1 shape: the relocate transaction gets back its caller-owned rollback accumulator with the move call inside the `try`; `derive-from-files.py` gets back the `_has_step_start` dedup guard matching `write-context.update_context`; `register-capability.py`'s `_write_registry` goes back to the temp-file + `os.replace` atomic write matching `relocate-capability._write_config`; and the implement command's final step is renumbered `5.` → `7.` in its source node (`nodes/implement/complete.md`), with the assembled body regenerated and the golden baseline re-blessed. Each behavioral fix is pinned by a regression test, and the restored one-line comments/docstrings explaining the guards come back with the code so a future refactor pass cannot strip them as redundant again.
