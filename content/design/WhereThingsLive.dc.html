Where your own work is kept
Everything you add lives in your repository, in plain files you commit and review. Nothing is stored inside the extension, so an upgrade cannot overwrite it — and cannot silently take it away either.
Yours — committed with your code
.specify/companion.yml
The one configuration file. Which nodes run, in what order, the hooks you attached, the template sections you replaced, where a verdict routes.
.specify/companion/nodes/<step>/<id>.md
A replacement for a node that ships with Companion. Same id, your words. Pressing Make it mine on a node writes exactly this file.
.specify/companion/nodes/specify/draft-spec.md
.specify/companion/nodes/<id>.md
A brand-new node of your own, at the top level rather than under a step. It runs where a hook names it, so one node can be attached in several places.
.specify/companion/nodes/review.md  →  { type: node, ref: review }
.specify/companion/fragments/<name>.md
The replacement body for one section of a template — addressed by the section's own heading, so there is no marker syntax to learn.
.specify/companion/workflows/<name>.yml
A whole named configuration you can switch to. Same shape as companion.yml; the nodes and fragments above are shared across all of them.
